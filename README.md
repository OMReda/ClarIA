## What it does

ClarIA is a self-hosted platform that lets non-technical users explore tabular data through natural-language prompts. It runs entirely on your own infrastructure — the default setup uses a local Ollama LLM so your data never leaves the server.

**File support**
- CSV (auto-detects encoding and French number/date formats)
- Excel `.xlsx` and `.xls` — with a sheet picker when the file has multiple tabs
- Up to 10 MB and 100,000 rows by default (both configurable)

**Prompting**
- Type a question in French or English — the backend normalises it, fuzzy-matches column names, and routes it to the LLM
- If the model references an ambiguous column it can't resolve, it pauses and asks a clarification question before retrying
- Cloud providers (OpenAI, Anthropic, Gemini) use an LLM classification call to detect chart type; Ollama uses fast keyword matching to avoid extra latency

**Dashboard**
- Drag-and-drop grid layout — resize and reorder charts freely
- KPI cards with manual aggregations (sum, average, min, max, count) and optional column filters — built by you, not generated by the AI
- Dashboard layout is persisted per dataset

**Exports from any chart**
- PNG (high resolution via ECharts SVG renderer)
- CSV
- Excel (formatted)
- Power BI–ready `.xlsx` via Power Query

**Auth & access**
- Keycloak OpenID Connect — every endpoint requires a valid Bearer token
- `admin` realm role unlocks a full user management panel (create, edit, delete users, set passwords, force logout)
- Rate-limited to 30 prompts / hour / user (atomic Redis Lua counter — no drift on connection drops)

**Real-time feedback**
- WebSocket connection opens as soon as a prompt is submitted
- Progress events, fallback notices, clarification questions, and final results all stream live from the Celery worker via Redis pub/sub
- If Ollama is unreachable, the backend automatically falls back to the first configured cloud key and notifies the user

## How it works

```
1. Upload     CSV or Excel → backend detects MIME, sniffs encoding,
                             infers schema, stores a 20-row preview

2. Preview    AG Grid table shows the file — user can switch sheets
              or remove the file and upload a different one

3. Prompt     User types a question → POST /files/{id}/prompts
              Backend creates a DB record, pushes task to Celery
              Frontend opens a WebSocket immediately

4. Worker     Loads the DataFrame
              Fuzzy-matches any column references in the prompt
              Detects chart type (keyword or LLM classify)
              Calls PandasAI → LLM writes aggregation code
              Code runs in a DockerSandbox
              Result DataFrame → ECharts spec

5. Render     Worker publishes spec to Redis pub/sub
              WebSocket relays it to the browser
              ECharts renders the interactive SVG chart
```

## Architecture

```
Browser
  │
  ├─ dev:  Vite + basicSsl  (https://localhost:5173)
  └─ prod: nginx :80 (HTTP only behind your own TLS terminator)

nginx
  ├─ /api/*      → FastAPI :8000
  ├─ /ws/*       → FastAPI :8000   (WebSocket upgrade)
  └─ /realms/*   → Keycloak :8080  (OIDC token endpoint)

FastAPI (async, Uvicorn)
  ├─ POST   /api/v1/files                      upload + validate
  ├─ GET    /api/v1/files/{id}                 metadata + preview
  ├─ GET    /api/v1/files/{id}/data            full data (paginated)
  ├─ POST   /api/v1/files/{id}/prompts         enqueue → Celery
  ├─ POST   /api/v1/files/{id}/prompts/{pid}/clarify
  ├─ GET    /api/v1/files/{id}/dashboard-config
  ├─ PUT    /api/v1/files/{id}/dashboard-config
  ├─ WS     /ws/prompts/{id}                   pub/sub relay
  ├─ GET    /api/v1/provider-status            Ollama health
  └─ CRUD   /api/v1/platform-users/*           admin only

Celery worker  → PostgreSQL (SQLAlchemy sync)
               → Redis pub/sub (publish result)
               → Ollama / cloud LLM
               → DockerSandbox (code execution)

PostgreSQL 16   files / prompts / charts  (UUID primary keys)
Redis 7         Celery broker · pub/sub · rate-limit counters
Keycloak 26     realm: claria · client: claria-frontend
Ollama          any model — runs on same host by default
```

**Database:**  PostgreSQL in Docker/production · SQLite (in-memory) for the test suite — no external services needed to run tests.

## Quick start — Docker

**Requirements:** Docker Engine 24+, Docker Compose v2, ~6 GB free disk for the model.

```bash
# 1. Clone and enter
git clone <your-repo-url>
cd plateforme-restitution

# 2. Set environment variables
cp .env.example .env
# Edit .env — at minimum change POSTGRES_PASSWORD and KC_ADMIN_PASSWORD

# 3. Start everything
docker compose -f docker/docker-compose.yml up --build

# 4. Open
http://localhost
```

> [!NOTE]
> On first start, Ollama pulls whichever model is in `LLM_MODEL`. The default in `.env.example` is `qwen2.5-coder:7b` (~4.7 GB) — this is **a personal choice made during development, not a requirement**. Any model on [ollama.com/library](https://ollama.com/library) works. Pull it with `ollama pull <model>` and set `LLM_MODEL=ollama/<model>` in your `.env`. Larger models (14B+) produce more reliable aggregations; smaller ones are faster but more error-prone.

> [!NOTE]
> The worker will not accept prompts until the Ollama healthcheck passes. `start_period` is set to 120 seconds to allow time for the model to load.

**Keycloak:** The `claria` realm is imported automatically from `infra/keycloak/claria-realm.json`. Set `KC_ADMIN_PASSWORD` in `.env` before the first start.

## Local development

### Backend

> [!WARNING]
> Python 3.11 is strictly required. PandasAI 3.x does not support Python 3.12+.

```bash
# 1. Create and activate virtualenv
python3.11 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 2. Install dependencies
pip install -r backend/requirements.txt
pip install -r tests/requirements-test.txt

# 3. Start backing services (no Ollama needed for local dev)
docker compose -f docker/docker-compose.yml up postgres redis keycloak -d

# 4. Run migrations
alembic -c backend/alembic.ini upgrade head

# 5. Start API server
uvicorn backend.main:app --reload --port 8000

# 6. Start Celery worker (separate terminal)
celery -A backend.workers.celery_app worker --loglevel=info
```

### Frontend

```bash
cd frontend
npm install
npm run dev
# → https://localhost:5173  (self-signed cert — accept the browser warning)
```

The Vite dev server proxies `/api`, `/ws`, `/realms`, `/resources`, `/admin`, and `/js` so the frontend talks to your local backend and Keycloak transparently.

### Tests

```bash
pytest tests/ -q                                          # all 141 tests
pytest tests/ --cov=backend --cov-report=term-missing     # with coverage
```

The full test suite runs against an in-memory SQLite database. No Docker, no Ollama, no network access required.

## Supported chart types

| Type | Detected by | Example French prompts |
|---|---|---|
| **Bar** | `barre`, `par région`, `par catégorie`, `par` | "Ventes par région", "Montant par catégorie" |
| **Line** | `évolution`, `tendance`, `par mois`, `par date` | "Évolution des ventes par mois" |
| **Area** | `aire`, `cumulé`, `surface` | "Cumul des revenus sur l'année" |
| **Pie** | `camembert`, `proportion`, `pourcentage`, `répartition` | "Répartition par type de produit" |
| **Scatter** | `corrélation`, `nuage`, `vs`, `versus` | "Corrélation entre prix et quantité" |
| **Histogram** | `distribution`, `histogramme`, `fréquence` | "Distribution des montants de commande" |
| **Radar** | `radar`, `toile`, `spider` | "Comparaison des indicateurs en radar" |

## Privacy & security

**Data privacy**

- `LLM_PROVIDER=local` **(default):** PandasAI passes up to 10 sample rows to Ollama. Ollama runs on the same host — data never leaves the server.
- `LLM_PROVIDER=openai / anthropic / google:` sample rows are sent to the external API. A warning is logged on every such request. Operators must obtain appropriate user consent.

**Authentication**

- Every HTTP and WebSocket endpoint validates a Keycloak-issued JWT (RS256).
- The issuer is validated by realm suffix rather than hostname, so the platform works correctly behind any reverse proxy, ngrok tunnel, or custom domain without changing config.
- The `admin` realm role is required for all `/platform-users/*` endpoints.
- WebSocket connections verify token ownership before subscribing to the Redis pub/sub channel.

**Code execution**

- LLM-generated Python code runs inside a **DockerSandbox** (pandasai-docker), isolated from the host filesystem.
- The Celery worker container mounts `/var/run/docker.sock` to spawn sandbox containers. In production, consider running Docker in rootless mode or using Sysbox to reduce the blast radius of this privilege.

## Future directions

These are areas being considered for future development. Nothing here is on a fixed timeline or guaranteed.

- **Conversation history** — follow-up prompts that reference previous results ("now break that down by region")
- **Scheduled reports** — automated dashboard snapshots delivered by email on a cron schedule
- **Multi-dataset joins** — ask questions across two uploaded files simultaneously
- **Custom chart templates** — save and name ECharts configurations for reuse
- **Role-based dataset access** — share a specific dataset with a user without granting admin rights
- **Better local model support** — improved prompt engineering and structured output parsing to reduce failures on smaller Ollama models
- **i18n** — multi-language UI (the backend is already language-agnostic; only frontend strings need translating)
- **Audit log** — per-user history of prompts and exports for compliance use cases

## Known limitations & feedback

The project is functional and fully tested, but it is still in active development.

- **Local LLM results vary by model and data.** Ollama worked well during development, but output quality depends on the model you choose and your specific data shape. `qwen2.5-coder:7b` was used while building the app — you are not tied to it. If results are poor, try a larger model or switch to a cloud provider from the settings panel.
- **PandasAI v3 is relatively new.** Some data shapes — deeply nested columns, mixed types, non-standard dates — may produce incorrect or empty results without a visible error.
- **Chart type detection can misclassify** on ambiguous prompts, especially with local models where classification is keyword-based.
- **The UI is French-first.** Error messages, labels, and example prompts are in French. No i18n system exists yet.
- **Keycloak needs manual configuration for production.** The bundled realm JSON is a starting point. You will need to set your own redirect URIs, client secrets, and email/SMTP settings.
- **Docker socket access is a privilege.** The DockerSandbox requires it; this is a known trade-off documented in the security section.
- **Not tested for horizontal scale.** Multiple Celery workers are supported, but shared file storage and session state have not been validated in a multi-node setup.

**Feedback and bug reports are welcome.** If something doesn't work, open an issue and include:
- File type and approximate dimensions (rows × columns)
- The exact prompt you used
- LLM provider and model name
- The error message or unexpected output

Pull requests are welcome too.
